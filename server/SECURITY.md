# 服务器安全设计与验收边界

此文记录当前实现及仍需部署层配合的保护，不表示服务已经做过完整攻防审计。

## 1. 信任边界

公网请求、Markdown、图片、路径、样式 JSON 全部视为不可信数据。
现有核心作为转换引擎复用，服务层负责远程调用边界。文稿中的提示词、链接或命令不构成执行授权。

```text
客户端 → 限流/字节上限/来源校验 → 清单与配置校验 → 私有任务目录
                   ↓                       ↓
            SQLite 持久状态       图片隔离校验 / 转换隔离执行
                   ↓                       ↓
             会话所有权校验 ← 校验后的 DOCX → 鉴权下载
```

## 2. 入口与滥用

- 免费匿名使用，不依赖付费账户、人工 Key 或前端内置共享 Key。
- 随机 256-bit 临时会话；Cookie HttpOnly、SameSite=Strict，HTTPS 时 Secure。
- 每次任务查询、取消、删除、下载均校验会话归属；其他会话返回 404。
- 不允许凭 jobId 公开下载；不向结果暴露服务器路径。
- 默认按实际连接 IP 做分钟限流，不信任任意客户端转发头。
- 创建任务 10/min、新会话 15/min、下载 30/min、其他访问 180/min，计数在 SQLite 中持久化。
- 只允许配置中的精确 Origin，拒绝任意站点的浏览器请求；CORS 不替代会话所有权。
- 同时上传 2 个、下载 4 个；HTTP 层最多 32 个并发连接处理，空闲连接较短。
- 会话、限流记录、任务记录和队列各有容量上限，防止无限增长。

IP 限制不能阻挡所有分布式滥用，也不能代替带宽清洗。匿名会话可以重新创建，因此仍依赖全局队列、真实 IP 和入口保护。
当前没有 CAPTCHA、WAF 配置或封禁后台；公网部署可按实际流量补充，不能宣称已经实现。

## 3. 上传与配置

- 在 multipart 解析前累计实际字节，Content-Length 缺失也执行上限；声明不一致拒绝。
- 上传有总时限，避免慢速传输长期占用资源。
- 限制字段/文件数、清单大小，重复 part、未声明附件、重复路径均拒绝。
- 相对路径 NFC 规范化；拒绝绝对路径、盘符、UNC、反斜线、控制字符、空段及 . / ..。
- 不靠用户 multipart filename 决定服务器写入路径。
- 内部 Markdown 名称唯一，避免平铺 CLI 输出互相覆盖；用户原路径仅作为任务逻辑信息。
- 配置字段白名单、枚举、颜色、字号、有限数值和页面可用区域检查。
- 禁止外部指定可执行文件、Shell、额外 Pandoc 参数、任意环境变量和输出目录。

## 4. 图片校验也在隔离环境内

API 只接收字节和检查路径/大小，不在主服务里解码不可信图片像素。
图片解码和重编码使用独立 Bubblewrap 子进程：

- 只挂载本次暂存输入，隔离其他任务和主目录，禁用网络。
- 文件格式需与 PNG/JPEG 声明匹配；拒绝损坏、动画、超像素或超大小输入。
- 重编码去掉附加负载和元数据，重编码后总资源字节也受请求预算约束。
- 图片校验进程虚拟地址空间限制 256 MiB，墙钟时限最多 20 秒；一次只运行一个图片校验进程。
- 失败直接拒绝任务并清理暂存文件，不把半验证输入交给转换队列。

这既限制解压炸弹，也避免将图像解析库的漏洞直接放在可以读取所有任务的 API 进程中。

## 5. 转换进程隔离

Bubblewrap 是必要条件，探测失败时转换端点拒绝受理，不回退为普通宿主子进程。

- 非特权用户命名空间；新 PID、IPC、UTS、网络等 namespace。
- 清空继承环境，仅传固定的运行必需变量。
- 仅只读挂载当前项目 core/cli、Conda 运行时、系统库和字体配置。
- 只读挂载本任务输入/配置，只允许写本任务输出；临时目录在独立沙箱内。
- 不挂载服务数据库、主目录、其他任务、SSH 文件、宿主机根目录或 Docker socket。
- 新网络 namespace 不提供外部网络接口；文稿无法请求内网服务或外部 URL。
- 去掉 capabilities，父服务死亡时停止沙箱，取消/超时杀掉整个进程组和 namespace。
- stdin 为 DEVNULL，不接管管理终端。

共享的只读运行时和代码必须保持为无凭据的运行环境；不要把业务密钥放进 Conda 目录、core/cli 或系统共享路径。
Bubblewrap 使用宿主内核，不等于虚拟机。内核、Bubblewrap、Pandoc、Pillow、XML 及 HTTP 依赖仍需维护安全更新。

## 6. 资源与故障

- 一个任务执行器顺序转换，每次一个文件，不因免费接口直接无限并发。
- 默认队列总容量 8、每会话活跃任务 2。
- 单文件/总任务/排队时限分别管理。
- 子进程限制虚拟内存、CPU 时间、单文件大小、打开文件数、core dump 和用户进程数。
- stdout/stderr 有界读取，不让大批诊断无限累积在 API 内存中。
- 生成 DOCX 要满足常规文件、大小、ZIP 成员/解压总量和必要结构检查，才发布下载信息。
- 业务数据预算和磁盘保留空间检查，在转换前预留单份输出空间。
- 取消等待实际执行停止；保留之前成功项，其余标未处理。
- 队列记录持久化；重启继续 queued，运行中被中断的任务明确失败，不假装成功。
- 正常退出也回收子进程；附带测试检查子进程不能在取消/超时后延迟写文件。

RLIMIT_AS 是虚拟地址空间限制，RLIMIT_NPROC 是用户级限制，它们不是所有子进程的总驻留内存配额。
生产应使用专用服务用户，并通过提供的 systemd 模板应用整服务 MemoryMax/TasksMax/CPUQuota。
用户级进程限制不要直接当成多租户系统的逐任务 cgroup。WSL 本地开发不宣称已具备生产 systemd 的总内存约束。

## 7. 数据与日志

- 服务数据目录权限 0700；生产单位 UMask=0077。
- 默认关闭 HTTP access log，应用不打印请求体、Cookie、Authorization 或临时会话 token。
- 公网只返回错误码、简短信息和 requestId；原始转换 stderr 不直接返回。
- CLI 默认报告留在本任务隔离输出目录，结束后清除，不作为公开诊断附件。
- 输入/配置在终态后清理，DOCX 默认保留 24 小时；到期先拒绝访问再回收字节。
- 主动删除需要归属校验，文件清理失败不会返回“删除成功”。
- 已授权并开始的下载不能撤回已传出的字节。
- SQLite 数据库不保存明文 token。服务只保存原始字节摘要和必要任务元数据用于幂等，不保存文稿正文到数据库。

## 8. 生产部署还要完成

1. 确认服务器系统、架构、用户命名空间策略及 Bubblewrap 可运行。
2. 使用专用普通用户；安装、审查并验证 systemd 资源限制。
3. 配置 TLS 和入口层连接/带宽防护，选择 Tunnel 或受控反向代理。
4. 配置准确 Origin、Secure Cookie，以及受信任代理下的真实 IP 传递规则。
5. 外部不能绕过入口访问转换端口；管理访问与业务访问分开控制。
6. 结合真实 2 核 2G 机器验证限额、磁盘/内存峰值、排队与告警。
7. 定期更新依赖锁定版本并回归，不把“固定版本”误认为永远安全。
8. 明确对用户展示上传去向、保留期限和主动删除方式。

本次没有修改云厂商安全组、DNS、Windows 防火墙，没有公开部署。
