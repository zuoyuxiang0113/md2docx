## Containers 演算模型

只计算 standard-2：1 vCPU、6 GiB 内存、12 GB 磁盘。运行期间平均 CPU 使用 0.5 vCPU。运行时长指容器活跃时长，包括等待休眠的时间，不等于纯转换耗时。每个场景假设独占账户当月包含额度。未比较相同吞吐或相同硬件性能。

- 内存包含 25 GiB-hours，超额 $0.0000025/GiB-second。
- CPU 包含 375 vCPU-minutes，超额 $0.000020/vCPU-second。
- 磁盘包含 200 GB-hours，超额 $0.00000007/GB-second。
- 基费 $5/月，按月收取，不随场景按小时折算。

令 H 为月活跃小时数：

```text
memory = max(6H - 25, 0) * 3600 * 0.0000025
cpu    = max(0.5H*3600 - 375*60, 0) * 0.000020
disk   = max(12H - 200, 0) * 3600 * 0.00000007
subtotal = 5 + memory + cpu + disk
```

| H | 内存 | CPU | 磁盘 | 小计（USD） |
| --- | ---: | ---: | ---: | ---: |
| 10 | 0.3150000 | 0.000000 | 0E-8 | 5.32 |
| 100 | 5.1750000 | 3.1500000 | 0.25200000 | 13.58 |
| 730 | 39.1950000 | 25.8300000 | 2.15712000 | 72.18 |

小计不含 Workers 超额、Durable Objects、持久存储、日志、超额出口、税费、汇率和运维。包含额度为账户级预算，其他应用会消耗。不要把内存 GiB 与磁盘 GB 混成同一单位。

自有服务器的现有月租金没有由用户提供，以 S 表示。新增计算租金可能为 0，不能因此说服务总成本为 0。完整月成本还应计入域名、备份、维护工时和已有服务器机会成本。

## 性能实测

sources/benchmark.py 使用合成数据，每类5次，共15次。每次新建私有临时目录，使用 Bubblewrap + limit_exec + CLI。记录 Sandbox.run 启动至返回的墙钟时间，不含 HTTP、上传、排队和下载。WSL Ubuntu-26.04 可见28逻辑CPU，没有限制为2核，也不是用户VM。结果在 sources/benchmark-results.json。

样本很少，最大值不是可靠 P95。输入不含真实用户文稿，短文48B、表格公式80B、长文17013B。不能把中位数当作生产 SLA，不能据此比较云平台性能或推导目标机并发。

raw child_highwater_kib 是 Linux 对已等待子进程报告的 ru_maxrss，只作原始观测，不代表 API、图片子进程与转换的同时内存总和，不用于给出内存容量结论。

## 模型演算

串行理论吞吐 3600/t，假设 t=5s 得720份/小时；70%占用得504份/小时。二者只是规划示例。

轮询约1.6秒间隔，忽略响应耗时：5*60/1.6=187.5次读取/分钟。当前Guard读桶180/分钟，代理聚合时存在冲突风险。真实请求时序、缓存与退避会影响实际值。

rlimit 的1GiB是虚拟地址空间；systemd MemoryMax=768M限制整服务组内存；不能相减后直接推算安全并发。图片解码可能与文档转换重叠。
