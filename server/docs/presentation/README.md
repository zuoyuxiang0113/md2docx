## 交付文件

- output/MD2DOCX-六人架构与部署演进.pptx：完整可编辑PPT，逐页讲稿与来源写入演讲者备注。
- 逐页演讲稿.md：六人分工、逐页时长、完整口述与交接。
- diagrams/架构图合集.drawio：12张可编辑图，使用 diagrams.net 打开。
- diagrams/*.mmd：Mermaid图源，可在支持Mermaid的编辑器继续修改。
- 来源与量化口径.md：官方资料、费用计算、实测范围和源码函数索引。
- sources/deck-content.json：全部页文案、讲稿、图节点、边与坐标。
- sources/prepare_content.py：内容及图源生成器。
- sources/build_slides.mjs：Artifact Tool原生文字、表格、连接线的构建逻辑。
- sources/benchmark.py / benchmark-results.json：可复现的WSL合成性能样本。
- sources/cost-model.json：逐场景完整精度费用。

PPT中表格、文字和关系图均为原生对象，可以直接编辑。Mermaid侧重语义，draw.io保留本次节点布局。无Cloudflare容器性能实测，费用不是最终整账单。VMware转换失败仍未解决，本次只整理资料，不修改业务逻辑或发布公网。

## 校核安排

系统上下文、容器视图、组件视图、关键代码关系来自源码交叉检查。AI生成并核对图后，仍需要团队人工签核，不声称已经完成他人的人工审核。

- 讲者1：核对产品边界、现状证据和VM失败状态。
- 讲者2：按源码逐条核对12张图中自己负责的节点与调用边，确认C4“容器”不是Docker。
- 讲者3：核对文件/数据库顺序、清理失败、生命周期和故障路径。
- 讲者4：重新查官方价格，核对演算假设和目标机性能实测。
- 讲者5：确认ADR中已采用、建议、待验收的状态。
- 讲者6：确认当前排空重启限制及未来零停机前提，演练后再更新验收结论。
